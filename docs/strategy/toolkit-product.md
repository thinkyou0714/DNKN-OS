# 電気設計計算ツールキット — 商品設計と販売運用

対象: `web/toolkit.html`（実装: `lib/toolkit/` ＋ `web/src/toolkit/`）。
月10万円戦略の中での位置づけと、販売開始までの運用手順をまとめる。

## 1. 商品の位置づけ（なぜこれを作るか）

月10万円（手取り）の3層構造のうち、本ツールは**「通年の底」を担う第2の柱**:

| 層 | 商品 | 季節性 |
|---|---|---|
| 繁忙期の山 | 二次対策教材・AI添削キット（note/Kindle） | 10〜12月に集中 |
| **通年の底** | **設計計算ツールキット（本商品）** | **試験サイクルと無関係** |
| 安定基盤 | メンバーシップ | 通年（解約率管理が生命線） |

無料の計算サイトが飽和している市場で有料が成立する条件は調査で特定済み:

1. **根拠解説**（式の導出・係数の意味・よくある誤解・一次情報の読み方）— 各モジュールに全文収録
2. **無料ツールにない領域**（ディレーティング・寿命推定・熱計算）— 有料枠に配置
3. **計算書出力**（品名・設計者・日付・改訂記号つきの印刷/PDF）— 有料枠
4. **ブラウザ内完結**（データ非送信）— 法人ユーザーの機密面に刺さる差別化。UI に常時明示

## 2. 収録モジュールと無料/有料の線引き

単一の真実は `lib/toolkit/index.ts`（`tier` フィールド）。

| モジュール | 枠 | 線引きの根拠 |
|---|---|---|
| 電圧降下（直流・単相2線・単相3線・三相3線／力率・リアクタンス対応） | 無料 | 無料サイト飽和領域。「35.6 の正体」「k の取り違え」解説で信頼を作る |
| 力率改善コンデンサ容量 | 無料 | **電験（電力・法規）の頻出論点＝検索流入の入口**。学習アプリとの相互送客が最も効く |
| 抵抗ディレーティング | 無料 | 単純計算・集客用 |
| 短絡電流・遮断容量チェック | 有料 | %Z 法。遮断器選定の要で、間違えると波及事故になる領域 |
| 接地抵抗の許容値チェック | 有料 | A/B/C/D種＋B種の k/I1。法規知識がそのまま実務に効く |
| コンデンサ ディレーティング＋寿命推定 | 有料 | 10℃2倍則＋リプル自己発熱＋周波数補正係数。無料ツールにほぼ無い |
| 半導体 熱計算（定常＋繰り返しパルス） | 有料 | θja の罠と Zth(D,tp) の解説込み。実務価値が高い |
| 基板パターン許容電流（IPC-2221） | 有料 | 電子設計者向け。適用限界の解説込み |
| 計算書出力（全モジュール） | 有料 | 「提出できる体裁」が支払い理由になる |

収録は「電気設備系（電験の論点と直結）→ 電子部品系（信頼性設計）」の順。
前半4つが学習アプリからの送客先、後半4つが電子ハード設計者向けという二層構成になっている。

判定は共通3値（`judgeUsage`: 閾値の90%以下=合格 / 閾値以下=合格・余裕小 / 超過=不適）。
閾値はユーザーが変更でき、既定値は一般的なディレーティング慣行（50%/80% 等）。

## 3. 技術構成（アップロード仕様書からの意図的な変更点）

元仕様（Next.js + Tailwind の別リポジトリ・ビルドフラグで無料/有料 2 ビルド）から
次の2点を変更した。**仕様の本質（完全静的・クライアントサイド完結・localStorage のみ・
単位明示・レスポンシブ・印刷計算書）はすべて満たしている。**

1. **denken-os 内の独立ページとして実装**（Next.js 不使用・esbuild 単一バンドル）
   - 既存のデプロイ（GitHub Pages）・CI（verify）・デザイントークン・SW オフライン対応を
     そのまま再利用でき、保守が1系統で済む。
2. **無料/有料はビルドフラグでなくライセンスキー**（既存の ECDSA 基盤に sku="toolkit" を追加）
   - 単一デプロイで済み、zip 配布より流出耐性が高い（キーは個人紐付きで発行）。
   - `publicKeyJwk` 未設定の間は**全モジュール無料のまま**（学習アプリ Pro と同じ fail-open）。
   - 署名鍵は学習アプリと共通（keygen 1回）。sku が違うため Pro キーでは解錠できない。

## 4. 販売開始手順（3ステップ）

学習アプリのフリーミアム（`docs/strategy/monetization-setup.md`）と同じ鍵を使う:

```bash
# 1. 鍵ペア生成（済みなら不要。secrets/ は .gitignore 済み）
npm run license:keygen

# 2. 公開鍵を web/src/monetization-config.ts の publicKeyJwk へ貼る
#    （toolkit-config.ts は同じ鍵を参照する。purchaseUrl は toolkit-config.ts に設定）

# 3. コミット → main へマージ（GitHub Pages へ自動デプロイ）
npm run verify && git commit ...
```

販売のたび（購入通知 → キー発行 → メール送付）:

```bash
npm run license:issue -- --sku toolkit --email buyer@example.com   # 買い切り
```

## 5. 価格・チャネル（調査レポート準拠）

- **買い切り 4,980円**を基本線（無料計算サイト対比の価値=根拠解説＋計算書。相場上限 3,000〜8,000円の中庸）。
- チャネルは **BASE**（手取り約93%・日本語決済）を主軸に、note 記事（解説つき販売ページ）を併用。
  ライセンスキーはどちらでも「購入通知→手動発行」で開始し、月数十件を超えたら自動化を検討。
- 年次アップデート（規程改定・モジュール追加）は任意課金（1,000〜2,000円）として将来検討。
  サブスク強制は個人ユーザーの離脱を招くため行わない。
