# 帳票変更点抽出ツール — 商品設計と販売運用

対象: `web/sheet-diff.html`（実装: `lib/sheet-diff/` ＋ `web/src/sheet-diff/`）。
月10万円戦略における「第3弾・最も競合が薄い領域」の実装。

## 1. 商品の位置づけ

調査で特定した競合状況:

| 既存ツール | 価格 | 性質 |
|---|---|---|
| 方眼Diff / WinMerge / SuperXLe | 無料 | **汎用**のファイル/セル差分 |
| Excel Diff（Suntrap） | 有料 | 汎用 Excel 差分 |
| Diffchecker | オンライン | 汎用・**データを外部送信** |

いずれも「テキスト/セル位置の差分」であり、**設計帳票の突合には向かない**。
本ツールの差別化は次の3点で、これがそのまま価格の根拠になる:

1. **キー列で行を突合する** — 部品表・端子表は「品番で1行」が決まっている。
   行を並べ替えただけの版を「全行変更」と報告しない。汎用差分にはできない。
2. **各社雛形の吸収（列名エイリアス）** — 「品番」「部品番号」「Part No.」を同じ列として扱う。
   取引先ごとに帳票の書式が違う実務そのものに効く。
3. **ブラウザ内完結（データ非送信・保存もしない）** — 部品表は原価と設計そのもの。
   オンライン差分ツールに貼れない機密が対象になるため、法人利用で決定的な差になる。

## 2. 無料/有料の線引き

単一の真実は `web/src/sheet-diff/sheet-diff-config.ts`（sku は `sheetdiff`）。

| 機能 | 枠 | 根拠 |
|---|---|---|
| 突合と変更点の**画面表示（全件）** | 無料 | 集客の中心。ここを絞ると価値が伝わらない |
| **Excel ブック（.xlsx）の直読み** | 無料 | 「CSV に保存し直す」一手間が最大の離脱要因。入口で削る |
| Shift_JIS / UTF-8 自動判定・列マッピング | 無料 | 「使える」と分かる状態まで無料で届ける |
| 変更点一覧の **CSV 書き出し** | 有料 | 提出物になる＝支払い理由 |
| 変更点 **レポートの印刷/PDF** | 有料 | 同上（レビュー資料・変更管理記録） |
| **設定プリセットの保存** | 有料 | 反復利用＝継続価値。単発利用者は無料のまま使える |

`publicKeyJwk` 未設定のあいだは**全機能が無料のまま**（学習アプリ・ツールキットと同じ fail-open）。

## 3. 実装の要点

- `lib/sheet-diff/xlsx.ts` — **xlsx をブラウザ内で解く**（外部ライブラリなし）。xlsx は ZIP なので
  セントラルディレクトリを読み、標準の `DecompressionStream("deflate-raw")` で必要なエントリだけ展開する。
  中身の XML は Excel が生成する既知の構造だけを対象に抽出（共有文字列・リッチテキスト・
  インライン文字列・数式の結果・空欄セルの省略・複数シート）。**帳票を外部へ出さないという売りを
  保ったまま「Excel をそのまま放り込める」を実現する**のが狙い。
- `lib/sheet-diff/parse.ts` — RFC 4180 準拠の CSV/TSV パーサ（外部ライブラリなし）。
  区切り自動判定、クォート内改行、CRLF/CR/LF 混在、BOM、**Shift_JIS 自動判定**。
  Excel の日本語 CSV は今も Shift_JIS が多数派で、UTF-8 として読むと全行が変更に見えるため必須。
- `lib/sheet-diff/diff.ts` — キー突合（複合キー可）、セル単位の変更抽出、列の追加/削除、
  キー重複の検出、数値同値（`1.0` と `1`、`1,000` と `1000`）の扱い。
- `lib/sheet-diff/report.ts` — 変更点一覧（1変更セル=1行）と CSV / サマリ。画面と CSV は同じ並び。
- `web/src/sheet-diff/` — DOM グルー。**帳票の中身は localStorage にも保存しない**
  （保存するのは突合設定だけ。テストで不変条件として固定）。

## 4. 価格・販売

- **買い切り 6,800円**（調査レポートの第3弾想定価格。汎用差分より高いのは上記3点の差別化ぶん）。
- 発行: `npm run license:issue -- --sku sheetdiff --email buyer@example.com`
- チャネルは BASE を主軸（手取り約93%）。法人引き合いは個別見積（サイトライセンス）を想定。

## 6. 次の一手

- **シート選択 UI**: 現状は先頭シートを読む（複数シートがある場合はトーストで通知）。
  シートを選べるようにすると、1ブックに複数帳票がある実務に対応できる。
- **3世代比較**（旧→中→新）と変更履歴の累積レポート。
- **書式・セル色の差分**: 現状は値のみ。設計帳票では色分けが意味を持つことがある。
- 法人向け: 社内の複数帳票をまとめて突合するバッチ（サイトライセンス）。
